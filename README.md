#     people-detector-tracker
Тестовое задание для компании BND.

Этот проект выполняет детекцию и трекинг людей на видео, объединяя возможности YOLO (для обнаружения объектов) и фильтра Калмана (для предсказания и отслеживания движения объектов).


## Структура проекта

```
project/
│
├── src/                       # Исходный код
│   ├── detect_and_track.py    # Детекция и трекинг с использованием YOLO или YOLO + фильтр Калмана
│   └── kalman_tracker.py      # Реализация фильтра Калмана
│
├── weights/                   # Параметры модели YOLO
│
├── videos/                    # Тестовые видео
│
├── main.py                    # Точка входа: запуск детекции/трекинга
├── requirements.txt           # Зависимости проекта
└── README.md                  # Документация
```


## Установка

```bash
git clone https://github.com/dbelogortseva/people-detector-tracker.git
cd people-detector-tracker
pip install -r requirements.txt
```


## Использование

### Детекция с помощью YOLO
```bash
python main.py --input videos/crowd.mp4 --mode yolo
```

### Детекция и трекинг с помощью YOLO + фильтра Калмана
```bash
python main.py --input viseos/crowd.mp4 --mode kalman --stride 10
```


## Аргументы

| Параметр | Описание | По умолчанию |
|-----------|-----------|--------------|
| `--input` | Путь к входному видеофайлу | Отсутствует |
| `--output` | Путь к выходному видеофайлу | `outputs/detected.mp4` |
| `--model` | Параметры используемой модели YOLO | `weights/yolov8n.pt` |
| `--conf` | Порог уверенности детектора YOLO | `0.4` |
| `--mode` | Режим работы: `yolo` или `kalman` | `kalman` |
| `--stride` | Частота обновления YOLO при трекинге (используется в режиме `kalman`) | `10` |
| `--iou-thr` | Минимальное значение метрики IoU | `0.3` |


## Логика работы

1. В режиме `yolo`:
   - Для каждого кадра применяется инференс модели YOLO.
   - Полученные в результате инференса bbox'ы выводятся на изображение.
   - Измененные изображения собираются в единое видео и сохраняются.
2. В режиме `kalman`:  
   - YOLO используется не на каждом кадре (через `stride` кадров).
   - В промежутках между инференсом YOLO фильтр Калмана предсказывает положение каждого bbox.
   - Если на текущей итерации был посчитан инференс YOLO,
     то результат - сглаженное значение между предсказанием фильтра и YOLO.
   - Полученные bbox'ы выводятся на изображение.
   - Измененные изображения собираются в единое видео и сохраняются.


## Результаты

1. Реализовано отслеживание людей в реальном времени.  
2. Устойчивость к пропускам кадров. 
3. Возможность настройки частоты обновления YOLO (`stride`).  
4. Применение **фильтра Калмана** позволило:  
    - Увеличить скорость работы примерно в **5 раз** по сравнению с покадровым применением YOLO.  
    - Обеспечить **более стабильный трекинг** объектов между кадрами.  
    - **Сократить мигание bbox** и сделать визуализацию более плавной.

## Идеи по улучшению

1. Улучшить логику сопоставления детекций и треков (например, искать глобальный оптимум).
2. Оценивать не только метрику IoU для сопоставления bbox'ов, но еще и евклидово расстояние.
3. Дообучить модель YOLO на данных с определенной локации (если камера уличная, то она обычно расположена в определенном месте).
4. Динамически определять, на каких кадрах стоит запускать YOLO, а на каких кадрах достаточно воспользоваться предсказанием фильтра Калмана.  
   Например: обучить легкую модель, которая будет оценивать тепловую карту движения. Если тепловая карта резко изменилась, то применить YOLO, так как скорее всего поменялся поток людей или сдвинулась камера.
   Если тепловая карта практически не поменялась, то применить предсказание фильтра Калмана. Это поможет уменьшить вычислительные затраты.
6. Вместо фильтра Калмана попробовать использовать Байесовский фильтр.

Если есть возможность использовать алгоритмы линейной алгебры и статистики для оценки следующего положения bbox, то, на мой взгляд, на них стоит делать упор. **YOLO** отлично решает задачу обнаружения людей, но в классическом сценарии люди движутся с примерно постоянной скоростью, поэтому вызывать детектор на *каждом* кадре — не всегда оптимально. Разумнее реже запускать детекцию и между вызовами полагаться на предсказания трекера, периодически корректируя их новыми детекциями.
